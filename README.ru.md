# Dark Fabric

Локальная фабрика разработки через официальный Codex CLI. Принимает цель, исследует проект, строит план, пишет код в отдельных Git worktree, выполняет проверки, проводит независимое ревью и собирает результат в ветке миссии.

Подходит для разных проектов: веб-приложений, сервисов, инструментов и игр. Godot, .NET и другие инструменты нужны только соответствующему проекту. Локальный пульт сейчас на русском языке.

## Быстрый запуск на Windows и macOS

1. Установите **Node.js 24 LTS**, **Git** и [официальный Codex CLI](https://developers.openai.com/codex/cli/).
2. Выполните `codex login` в терминале.
3. Склонируйте этот репозиторий, перейдите в его папку и выполните:

```sh
npm run setup
npm run up
```

Откройте **http://127.0.0.1:4317**. Команды одинаковые для PowerShell и Terminal macOS. Если PowerShell блокирует npm.ps1, используйте `npm.cmd` вместо `npm`.

Setup устанавливает зависимости из lockfile, создаёт пустое состояние и проверяет подключение Codex. Ни один проект не подключается автоматически.

## Портал на localhost без запуска задач

Чтобы открыть только портал, выполните:

```sh
npm ci
npm run portal
```

Адрес: **http://localhost:4317** (также работает http://127.0.0.1:4317). Этот режим не требует подключения к Codex: он показывает сохранённые данные, позволяет задать настройки, ответить на вопросы и подготовить проекты. Исполнитель и удалённый bridge не запускаются. Остановка и пауза сохраняются; данные квоты могут быть устаревшими.

В разделе **Проекты → Новый проект** укажите название, цель и приоритет. Заявка сохраняется сразу; репозиторий и задачи появятся после запуска исполнителя. При потере ответа повторите сохранение: запрос не создаст дубликат. Регистрация существующего репозитория по-прежнему доступна через CLI ниже.

Портал занимает тот же порт и блокировку, что и фабрика. Если фабрика уже работает, просто откройте её адрес. Чтобы перейти из режима портала к выполнению задач, закройте портал (Ctrl+C или `npm run down`), затем выполните `npm run up`. Пауза очереди сама не снимается. Если нужно только изменить порт, задайте `port` в `.darkfabric/config.json` перед запуском. Другой каталог состояния: `npm run portal -- --home "/полный/путь/к/состоянию"`.

## Подключение проекта

```sh
node src/cli.js project add "/полный/путь/к/проекту" --name "Мой проект"
node src/cli.js project checks PROJECT_ID examples/checks.node.json
node src/cli.js mission PROJECT_ID --goal-file examples/goal.txt
```

Замените PROJECT_ID выданным идентификатором, а цель и команды проверок — своими. Репозиторий должен иметь первый commit. Незакоммиченные изменения исходной папки в миссию не входят. Для папки без Git используйте `project import`.

Проверенный результат хранится в отдельной ветке и рабочей копии миссии. Фабрика не перезаписывает исходную папку и не публикует изменения автоматически.

## Управление

| Команда | Действие |
| --- | --- |
| `npm run up` | Явный фоновый запуск |
| `npm run down` | Штатная остановка с ожиданием выхода процессов |
| `npm run service:status` | Проверка процессов |
| `node src/cli.js pause` | Запрет новых этапов; текущие могут завершиться |
| `node src/cli.js resume` | Снять паузу очереди работающего сервиса |
| `node src/cli.js status` | Сохранённые задачи, вопросы, квота и результаты |
| `node src/cli.js doctor` | Диагностика установки |
| `node src/cli.js questions` | Открытые вопросы |
| `node src/cli.js answer ID "ответ"` | Сохранить решение |

Остановка сохраняется между входами в систему. Пауза очереди сохраняется и после явного запуска. Состояние по умолчанию находится в `.darkfabric`; это личные данные, их нельзя публиковать в GitHub.

Новые установки используют `executionAccess: workspace`. Полный доступ включается только явным решением владельца. Лимиты Codex ожидаются штатно; обхода лимитов нет.

В разделе **Настройки** локального пульта задаются резерв лимита и период анализа сессий. По умолчанию фабрика приостанавливает обращения к Codex при остатке **10%** и проверяет восстановление квоты. Раз в **24 часа** она анализирует новые завершённые сессии и создаёт ограниченные задачи оптимизации расхода токенов. Изменения проходят обычные проверки и независимое ревью. Настройки сохраняются между запусками; пользовательская остановка не снимается автоматически.

Полное руководство: [запуск и устранение проблем](docs/getting-started.md), [настройки](docs/configuration.md), [эксплуатация](docs/operations.md), [архитектура](docs/architecture.md). Дополнительный удалённый пульт требует отдельного развёртывания и не нужен для локальной работы.
